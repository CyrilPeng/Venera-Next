# Network-favorite batch import protocol

Date: 2026-10-03.

- Collection is read-only. Folder identity is checked before loading and again inside the commit transaction. New folders are created only after successful collection. Cancellation/load failure leaves neither a new empty folder nor staged records; this intentionally fixes the former partial-write behavior.
- Prefetch and each page allow at most three attempts. RequestScope checks surround attempts, result application and final submission. Cancellation stops waiting/further scheduling, not necessarily every underlying JS/network operation.
- Oldest-first paging prefetches total pages and clamps the initial page to one. Page limits bound collection. Page-count/cursor types are validated and repeated cursors fail. In-batch IDs deduplicate; storage still deduplicates by id/type.
- Existing ordering rules apply before one outer SQLite transaction checks linkage, creates folders, writes linkage and inserts all records, with addComic savepoints inside. SQL failure rolls back the whole transaction; unrelated folders are not adopted and empty names are rejected.
- SQL returns NetworkFavoriteImportCommit with the folder, immutable id/type snapshot and actual added count. publishNetworkFavoriteImport only refreshes caches/tracking/views, without repeating SQL writes. The dialog stores success before publishing; publication failure retains Finished/the committed count and offers a separate Refresh retry. Retry neither collects nor commits again. A tracking observer failure does not prevent ordinary view notifications. Publication is not atomic with SQL; retried notifications have at-least-once semantics.
- State owns the scope; PopScope cancels when exit begins and disposal releases it idempotently. The old 500ms auto-close is removed; success/error remains for confirmation. Imported counts reflect actual committed records only.
- Ten focused tests cover prefetch retry/cancel, start-page bounds, duplicate IDs/cursors, SQL batch rollback/retry, new-folder rollback on metadata failure, ownership conflicts, disposal/exit animation and collection failure. Full 1385 passed before the additional empty-name assertion; final focused 10 passed. Analysis: zero errors/warnings, 25 infos; structure/76 entries, Python 63 (3 skips), Git dependencies passed. Logs: output/network-import-{full,final-targeted,final-analyze}.log.
- Real-source protocol coverage, very large datasets, native process termination, publication boundaries of other import entrypoints and cross-process notification recovery remain unverified. P6/P7/P8 are not complete.
