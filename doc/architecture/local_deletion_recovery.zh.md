# 本地删除恢复协议

日期：2026-10-03。本阶段基于 3a6acef；不宣称所有平台、断电或外部写入竞争已经验证。

删除前先核对记录路径、实际路径和拟保留引用。目录移动前，在 local.db 的 local_deletion_journal 表记录原路径、同级隔离路径和未提交状态。隔离路径包含本地日志 id 和时间标识，不覆盖已存在目录，父子候选只移动最上层一次。SAF 使用提供者的同目录 rename，不依赖其尚未实现的 createTemp 或 resolveSymbolicLinks。

| 状态 | 启动/下一次独占存储操作的恢复动作 |
|---|---|
| 未提交，隔离目录存在，原位置空闲 | 将隔离目录移回，成功后清除日志 |
| 未提交，隔离目录不存在，原位置存在 | 视为尚未移动或已回移完成，清除日志 |
| 未提交，两处均存在或均不存在 | 保留日志和现存文件，抛出恢复错误，不覆盖或猜测 |
| 已提交，隔离目录存在 | 仅删除隔离目录，成功后清除日志；不删除原位置的新文件 |
| 已提交，隔离目录不存在 | 清理已完成，清除日志 |
| 非同级/不符合隔离命名的异常日志 | 拒绝递归文件操作，保留证据 |

本地记录删除与 committed 标记必须在同一 SQLite 事务提交。需要关联清理时，复用三库事务和历史写队列；章节/不清理关联数据的路径使用本地事务。记录/目录/章节快照在异步预检前采集，事务内再次核对；暂存期间库记录改变则拒绝提交并恢复目录。恢复失败同时保留原错误与恢复错误。

LocalManager 初始化数据库后、加载库路径和任务前执行恢复；每次独占存储操作（含迁移）开始前再次恢复，未解决的恢复错误会阻止继续操作。已提交后的通知失败不会把文件错误地恢复到已删除的记录；清理失败保留持久日志供重试。已有旧版 local.db 只新增日志表，不改漫画/章节格式。应用同步快照不包含 local.db，不将这份机器本地清理意图同步到其他设备。

验证：原删除专项 22 项；日志恢复 7 项；最终日志与管理器重启专项 20 项；全量 Flutter 1330 项；分析零 error/warning、65 个既有 info；结构/75 项业务入口、Python 57 项（3 项平台工具跳过）、Git 依赖与格式检查通过。日志 output/deletion-journal-{targeted,recovery,final-recovery,full,final-analyze}.log。重开连接和重建管理器是恢复状态测试，不等于真实杀进程或断电试验。

仍需完成：SAF 提供者重命名/断连真机矩阵；强制终止和持久性故障注入；所有直接写入者纳入存储协调；外部进程换链及隔离路径外部改写；提交后通知失败的明确结果表达；恢复冲突的用户修复入口及阅读中暂存文件的生命周期。P6.7 继续部分完成。不要手工删除未提交隔离目录来解除恢复错误，它可能是唯一文件副本。

## Windows 子进程强制终止验证

新增 local_deletion_crash_probe/test，在独立 Dart VM 中执行生产 LocalDeletionJournal、SQLite 连接配置和事务工具；附加两个夹具数据库，使用最小 records 表检查三个数据库与日志状态。它验证恢复协议，不冒充完整 Flutter 应用或漫画仓储 schema 的杀进程测试。

每个检查点同步写入就绪标记后阻塞，父测试核对标记 PID 与启动句柄一致，再强制终止该 VM 并等待非零退出，不依赖子进程 finally。检查点为目录已暂存、三库删除/日志标记已写但事务未提交、事务已提交但尚未清理。前两种情况下记录回滚/保留且目录恢复；后一种情况下已提交记录保持删除，隔离目录清理且原路径的新文件保留；再次恢复无重复动作。

首轮 PID 检查发现 dart.exe 启动器会转交给 VM 子进程，测试未接受该结果；改为直接找到 dartvm 并显式传入 package_config 后，3 项专项和全量 1333 项通过。最终分析零 error/warning、65 个既有 info；结构/75 项入口、Python 57 项（3 项平台工具跳过）与 Git 依赖门禁通过。日志 output/deletion-crash-{targeted,full,final-analyze}.log。修正了上阶段最后新增重启测试遗漏的大括号 lint。

本机 Windows VM 终止协议有了证据；完整应用多线程读写、随机终止时点、非 Windows 平台、SAF 和断电/存储持久性仍未完成。
