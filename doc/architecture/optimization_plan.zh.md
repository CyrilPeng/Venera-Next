## 1. 目标与范围

目标是在保持既有功能和数据兼容的前提下，减少修改一个功能时需要理解的代码范围，收束循环依赖和全局状态，并清理没有生产用途的实现。

本轮采用渐进重构：延续 `app_shell/`、`app_runtime/`、`features/`、`foundation/`、`network/`、`routing/` 的现有组织方式。在职责复杂的功能域内部按需建立模型、服务、存储和视图边界，不要求所有目录套用相同模板。

本轮不包含产品功能扩张、UI 视觉改版、整体更换状态管理框架、拆分成多个 Dart package、批量升级依赖，以及未经数据验证的数据库结构重写。需要这些变更时另立任务，避免混入结构迁移。

当前约束以 [项目结构约定](project_structure.zh.md) 为准。本文提出的新入口和规则须在相应阶段同步更新结构文档、检查脚本和测试后生效。

## 3. 目标边界

### 3.1 各层职责

| 位置 | 应负责 | 应迁出的职责 |
|---|---|---|
| `app_shell/` | 页面入口和导航壳编排 | 数据读写、更新下载和同步算法 |
| `app_runtime/` | 依赖组装、启动顺序、运行模式、生命周期绑定 | 具体业务算法与页面渲染 |
| `routing/` | 将阅读/详情等数据目标转换为页面跳转 | 数据库查询规则、下载实现 |
| `features/<domain>/` 模型与策略 | 业务数据、纯计算、状态转换 | 根 context、导航、平台插件调用 |
| `features/<domain>/` 服务 | 用例编排、业务任务、依赖的小接口 | 对具体 Widget State 的查找与修改 |
| `features/<domain>/` 存储与适配器 | SQL、文件、源运行时等具体实现 | 弹窗、页面导航 |
| `features/<domain>/` 页面与组件 | 渲染、输入、提示和导航意图 | SQL、下载协议、重复的规则计算 |
| `foundation/`、`network/` | 跨域基础设施和技术能力 | 特定页面、功能域管理器、无明确用途的通用抽象 |

服务可使用 `ChangeNotifier` 等轻量机制；涉及 Flutter 绘制、视口或平台能力的代码保留合理适配层。纯业务规则尽量不依赖 Flutter。接口放在实际所属功能域，避免新建不断膨胀的全局 `common` 或 `core`。

### 3.2 公开入口与依赖方向

- 为需要区分业务和 UI 的功能域提供窄入口，例如 `comic_source_api.dart` 与 `comic_source_ui.dart`。最终命名在首次落地时统一。
- 业务入口仅导出稳定模型、契约和服务；不得通过间接 export 引入页面。
- 原 `<domain>.dart` 在迁移期间可作为兼容入口；调用点迁移完后删除无用途的兼容导出。
- 同域内部允许直接引用实现；跨域通过公开入口。架构脚本同步适配新入口，不通过忽略规则绕开。
- UI 层允许访问其他功能的公开 UI/路由入口，因此不追求功能域聚合图完全无环；重点是业务层无循环、无反向 UI 依赖。
- 现有 `Comic` 等类型先收窄暴露面。只有确认多个域共享且语义稳定后才迁移归属，避免为了消除一个 import 搬动整个模型体系。

业务层目标方向示例：阅读器通过章节访问和历史写入契约工作；同步通过导出/导入接口工作；本地库通过数据目标交给路由打开阅读器；运行时绑定具体实现与变更通知。

## 5. 分阶段任务与退出条件

### P0：建立可信基线

任务：

1. 记录起点 commit、未提交改动和已知失败；保留用户现有改动，不擅自 stash、reset 或提交。
2. 核对分析目录与生成文件，显式排除确认的构建产物；真实测试文件移回正式测试目录。不得通过排除整个源码/测试目录消除诊断。
3. 记录结构报告、全量测试结果和新生成的覆盖率；注明平台依赖跳过项及原因。
4. 扩展依赖报告，区分业务与 UI 入口，报告强连通分量和反向依赖；现存例外有清单、理由和移除阶段，禁止新增例外。
5. 在固定设备、构建模式和合成数据集上记录阅读切章、快速跳页、长图滚动、目录扫描、同步、批量导入的耗时/内存。重复运行记录波动，按噪声设门槛，不预先编造性能数字。

产物：基线报告、适用的分析排除规则、边界检查增量及脚本测试、性能场景说明。

退出条件：正式源码无 error/warning；既有 info 有清单；测试失败和跳过可复现且有归属；新增架构违规能被 CI 阻止；没有把基线失败默认为正常通过。

### P1：清理有证据的冗余

任务：

1. 核对 `Channel<T>` 的生产引用、测试引用和结构脚本描述；无现存用途则删除实现、专属测试及过时约定。
2. 核对 `components/components.dart` 的入口用途及脚本特殊处理；确认冗余后移除导出文件，保留实际使用的组件。
3. 生成可达性/公开符号候选清单，分类为可删除、测试工具、兼容协议、动态入口或待调查。
4. 核对已跟踪的临时脚本、日志、实验输出与重复工具。只处理确认在仓库维护范围内的文件，不递归清理用户工作目录。
5. 比较直接依赖和真实使用情况。Git 插件、原生插件注册、平台构建依赖、assets 与 JS 引用都计入检查；不以 Dart import 缺失直接删除包。

退出条件：每次删除具备引用检索、入口核对和验证记录；没有为了删代码而保留无生产意义的替代实现；不以减少固定行数为验收标准。

### P2：建立业务边界，完成首批可复用服务

任务：

1. 在漫画源、阅读器、本地库、历史、收藏和同步域逐步建立业务/UI 入口，并同步结构约定。
2. 提取 `SourceUpdateService`，承接单源更新、批量检查、取消、去重、仓库 revision 校验及结果状态。复用 `SourceRepositories`、管理器和已有安装流程，不另造一套下载/安装实现。
3. 页面负责弹窗和提示；CLI 直接调用服务并输出结构化结果。保留现有 CLI 参数、输出协议和退出行为，发现行为缺陷另列修复。
4. 将 `LocalComic.read()` 拆为阅读目标/初始位置计算与路由适配，保留下载章节 ID 和历史位置语义。
5. 明确跨域接口所有者：章节访问、历史写入、收藏查询、同步数据参与者仅暴露实际用到的方法。

退出条件：CLI 和业务服务不导入页面类；本地漫画模型不使用 context/导航；更新检查无需挂载 Widget 即可测试；同源重复更新、取消与仓库变化仍符合现有契约；新入口不会间接导出 UI。

### P3：设置类型化

任务：

1. 梳理阅读设置字段、默认值、合法范围、空值、继承与旧值迁移，先从现有测试提炼真实优先级。
2. 新增不可变的 `ReaderSettings` 与设置解析器。解析器输入全局、设备、单漫画配置及启用标志，输出有效配置和必要的来源信息。
3. 用设置存储适配器保留现有 JSON key 和持久化格式；强类型 API 逐项替换页面、手势、布局及自动阅读中的动态读取。
4. 集中校验未知枚举、错误类型、越界数值和缺失字段；保留同步排除字段和未知扩展字段的既有兼容语义。
5. 后续迁移同步、网络与外观配置；通过边界检查禁止已迁移模块重新引入字符串键。

退出条件：阅读器不再直接访问动态配置 Map；设置继承、单本/设备开关、长按兼容迁移及即时生效均有行为测试；原子写入、备份恢复、导入/同步结果不变；旧配置可往返读写。

### P4：显式生命周期与任务所有权

任务：

1. `Init` 缓存进行中的初始化 Future，明确未启动、初始化中、就绪与失败语义。并发调用共享一次执行；等待者收到失败；重试策略显式定义。
2. 审计所有 `ensureInit()` 调用，防止新规则引入自等待；明确启动依赖和关键/可选服务失败策略。
3. 拆出 `bootstrapCore`、交互模式绑定、无头模式绑定。需要插件的服务仍可初始化 Flutter binding，无头模式不要求根 Navigator 或窗口 UI。
4. 服务通过构造注入路径、客户端、存储、时钟等依赖；构造函数不自动启动定时器/窗口监听。运行时统一调用 `start()/dispose()`。
5. 将阅读图像加载、预取和源请求绑定到会话。共享请求采用订阅/引用所有权，最后一个使用者离开时才取消底层请求。
6. 扩展现有 `RequestScope` 的使用时核对 `dispose` 与 `cancel` 的不同语义，避免通过命名猜测行为。文件导入取消保留提交阶段的原子性。
7. 分步替换 `GlobalState.find` 为明确控制器/回调/监听；不引入另一个全局 State 查找器。

退出条件：并发初始化只执行一次，失败等待者结束；重复启动不重复订阅；销毁后无更新回调；阅读器退出不取消其他拥有者的请求；无头核心服务可在没有 Widget 树时执行；已迁移服务测试无需全局 reset 开关。

### P5：阅读器重构

任务按顺序实施：

1. 提取阅读位置模型，明确源图片索引、章节 ID、可视页码、双页和拆页偏移的对应关系。持久化位置沿用现有语义，视口位置不直接当作历史页码。
2. 提取页码映射、首图单页、评论尾页、模式切换和跨章策略，先建立行为测试。
3. 引入 `ReaderController` 管理阅读状态和命令；视图接收不可变状态、发送动作，逐项移除对祖先 `ReaderState` 字段的直接写入。
4. 复用 `loadReaderChapterImages` 并注入章节访问依赖，保持本地优先、按章节 ID 查找和缺失文件在线回退。
5. 将 `images.dart` 中画廊、连续、瀑布流视图拆开，定义共享视口协议用于定位、滚动和自动阅读。不同模式的特殊行为保留在相应适配器中。
6. 将 `scaffold.dart` 拆为阅读壳、菜单、进度和设置组件；保留键盘、无障碍、菜单锁定和安全区行为。
7. 历史保存、阅读时长、平台方向/亮度/音量、同步触发由会话/适配器管理；优先复用现有 `ReadingSessionTracker`、`AutoReadingController`、`WaterfallChapterFlow`。

退出条件：七种模式及自动选择模式通过回归；图片/章节/视口三种位置语义可解释；自动阅读暂停原因、长图终点、跨章等待和重试保持；设置范围与即时生效保持；快速跳页、退出、前后台切换没有迟到状态写入；固定设备性能不超过 P0 约定的回退范围。

### P6：存储、收藏、导入与同步

任务：

1. 将收藏/历史/本地库模型与 SQLite 行映射、查询和迁移分离；SQL 收敛到各自 repository，业务事务由服务明确组织。
2. 拆分收藏 CRUD、排序、稍后阅读和追更协调；保留现有表结构和收藏身份语义，复用 `sqlite_connection.dart`。
3. 本地库拆分目录访问、元数据存储、下载队列与恢复操作；导入器沿用 `DocumentImportSession`、`comic_storage` 和 `local_storage_guard`。
4. 将 WebDAV 在线库拆成配置、目录发现、快照/缓存、同步调度、漫画源适配。以实例保存运行状态，注入已有 `WebDavLibraryOps` 和缓存。
5. 应用数据同步拆成调度、传输、快照导入导出与 UI 状态。窗口关闭监听和前后台触发移到运行时适配器。
6. 用窄接口连接数据参与者；保留下载导入期间不回传、pending 标记、配置排除、版本检查及冲突语义。
7. 仅在原子性有充分保证时替换实现；数据库迁移不是本阶段默认任务。

退出条件：使用旧数据夹具完成读写/导入/恢复；失败注入下不留下半入库记录或半替换快照；排序、稍后阅读和追更通知保持；导入与存储迁移互斥；同步三种模式和重启后的 pending 状态保持；WebDAV 路径、缓存失效和增量同步结果一致。

### P7：解析器与技术重复流程

任务：

1. 将漫画源解析按搜索、分类、收藏、图片和评论等能力拆成注册/解析单元，保留入口校验、错误上下文和 JS 桥接边界。
2. 保持 `assets/init.js`、公开 JS API、回调名称、源 key 和持久化源格式兼容。测试使用仓库最小示例与合成源，不依赖第三方在线源。
3. 对更新、图片下载、归档下载、同步和导入的重复流程建立对照表：哪些是相同机制，哪些是业务差异。
4. 仅提取实际重复且语义一致的限流、进度、重试或取消原语；HTTP、JS 和文件转换可保留不同适配器，不建设万能任务框架。
5. 统一新代码的结构化错误：区分失败、取消和不支持，保留原始异常；错误翻译在 UI/CLI 边界处理。为旧 `Res<T>` 建适配，不全库同时替换。
6. 按同样标准审查版本比较、路径处理、文件排序、归档元数据和日期格式，优先复用已有公共实现。

退出条件：源解析与生命周期测试保持；最小源可运行；取消不被当作成功或普通失败重试；错误仍能定位到源/能力/操作；每项公共抽象有真实调用者且删除了对应重复实现。

### P8：退出兼容层与固化约束

任务：

## 9. 总体验收标准

完成应同时满足：

1. 业务服务与模型不依赖 Widget 页面、根 context 或具体页面 State；已迁移业务入口不间接导出 UI。
2. 关键业务层循环依赖已消除；保留的 UI 导航环有分类说明；CI 阻止新增业务环和反向依赖。
3. 阅读器通过明确控制器/协议协作，状态不再由子视图任意修改；设置解析与页码映射集中且可独立测试。
4. 已迁移服务有清晰依赖、初始化失败传播和释放机制；测试不依赖清空生产单例来隔离状态。
5. 所有删除项有用途判定；无已迁移完却遗留的兼容层；没有仅为降低行数而把耦合移到多个文件。
6. 数据/JS/CLI 兼容和核心行为回归通过；没有未说明的新失败、测试跳过或平台限制。
7. 性能在 P0 约定的波动范围内；覆盖率采用新生成结果，关键策略与失败路径有行为覆盖。
8. 结构文档、边界脚本、CHANGELOG 和实际代码一致。

文件长度只用作审查提示：超过约 800 行的手写文件需检查是否存在多个职责，不设硬性行数门槛。业务/UI 依赖、动态设置调用、生产全局状态和待清理候选数量按阶段记录趋势，不使用单一总行数或全库覆盖率衡量成功。

**剩余工作默认安排一次最终本地全量回归，包含覆盖率；每个小修复、提交和批次结束不再自动全量测试或构建。** 这是减少重复的默认执行规则，必要的追加验证必须有下面列出的触发依据，既有 CI 必需检查不变。

| L3：最终候选 | R1–R3 技术收尾、退出文档和发布资产就绪后冻结候选输入；执行全量 `flutter test --no-pub --coverage`、严格分析、格式、结构/架构、Python、版本及 Git 依赖等现有门禁，完成真实 CLI、SDK、平台和性能矩阵 | 将测试、覆盖率、构建和人工/性能结果关联到真实候选输入；没有缺项才完成原方案 |

1. 共享初始化、存储协调、请求原语、工具链或依赖发生实质变化，无法通过消费者清单和定向集界定影响；先记录变更、证据缺口及需扩大的检查。

3. L3 后修改了相关生产代码、测试、验证脚本、依赖或运行资产，最终证据已失效；先定向验证修复，重新稳定候选后补齐受影响的最终门禁。旧全量仍是历史记录，不能冒充新输入通过。
