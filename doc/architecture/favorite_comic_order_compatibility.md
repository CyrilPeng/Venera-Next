# Comic reorder saves and original host ownership

Implementation baseline: `5adde85f555b45ec508d1f0da8835d16cb38688f`.

LocalFavoritesPage captures the original folder when constructing its Reorder menu and calls comic_reorder_page.dart with its observed manager and original context. Retained menu and reverse/drag/retry actions check the original page, route, application/window and database. Initial comics, manager identity, generation and data path are captured once. Navigation retains the nearest Navigator and AppPageRoute behavior. No caller waits on the push Future: each accepted save belongs to the editor's existing save lifecycle, so Navigator destruction need not finish a presentation Future.

Each edit captures a detached complete-order snapshot before submitting it to SettingsSaveState. Original application/window registrations are established before persistence runs. AppDataOperations admission checks manager identity, generation and data path again, and verifies that the folder still exists. A retired queued target performs no write and does not create an unrepairable cancellation error. A valid accepted write is allowed to finish after the initiating page disappears or its original host begins closing. Host replacement does not transfer the accepted wait or failure.

Order persistence remains the existing manager mutation queue and FavoritesRepository transaction. The transaction assigns display_order for each (id,type), without deleting/reinserting rows or changing other columns. This is idempotent assignment: explicit retry uses the same captured order for notCommitted, committed and unknown failures. It must not be confused with incremental creation/rename, whose replay policy is different. A later successful accepted assignment can repair its own earlier failures. The editor's duplicate pending-save/revision/window-migration implementation is removed.

Parent-list callback assignment and the late navigation-completion rebuild are removed. The parent already owns a manager listener and query admission; committed order is observed through that path. A retargeted parent therefore keeps its own folder's list. The editor's current route alone can accept back/help/reverse/drag actions. Existing list/gallery sizing, ComicTile contents, color calculation, 100ms desktop/500ms mobile drag delays and route animations remain.

SettingsSaveState adds protected mayLeaveSettingsAfterSaveFailure, default false. Comic reorder opts in only when its original target has retired. Leaving still waits for accepted saves and uses maybePop on the captured current route, respecting other PopEntries. Dismissing a retired page neither repairs the failed save nor releases its original error registration; the original application/window can still report the same error and stack. Ordinary settings retain their existing failure-blocked return and explicit retry behavior.
