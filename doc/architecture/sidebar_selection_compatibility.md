# Chapter selection and sidebar lifetimes

Implementation baseline: `a5435f3c992241b7f4844638aab56842c3c2e965` (work started 2026-10-08).

## Presentation and ownership

SideBarRoute keeps its existing side-panel layout, slide transition, safe-area padding, colors, width, barrier label and nonzero pointer-down policy. It now exposes disposal and owner-admission hooks. Retained barrier callbacks and the iOS gesture start predicate require that original route to be current and its owner to remain active. The existing iOS gesture controller still owns the original route and animation controller; its implementation is unchanged.

showSideBar reuses WindowSelectionTask and keeps the nearest Navigator. It registers the original application/window before presentation and owns only the route it creates. Typed results now come from that route. Back/barrier dismissal returns null. Whole-Navigator disposal ends the wait even before the first page build. Failed removal ends presentation waiting with the original failure chain, retains the exact route in the original host and permits explicit cleanup retry. A presentation error observer records the original error/stack for callers that only open a sidebar; awaiting callers still receive the failed original future, and the host still owns failed cleanup.

Ordinary download captures the chapter IDs and titles shown at opening. Already-downloaded chapters stay checked and unavailable; Download All excludes them, while Download Selected retains selection order. The source/library/comic snapshots, duplicate-download guards, task constructors and queue implementation remain. The selector owns its original route, Navigator, host and input generation. Covered, frozen, replaced or removed owners cannot change selection or submit through retained controls. Confirmation publishes an immutable index list by popping the original route; a failed pop followed by Back therefore cannot publish an earlier side-channel assignment. The caller rechecks its original comic/host before queue publication and maps indices through the displayed chapter snapshot.

ReaderSidebarBinding uses the same route admission hook and schedules disposal completion after synchronous tree finalization. A surviving binding releases its borrowed interaction pause after never-built or built Navigator disposal and remains available to open another sidebar. Its existing close, release-error and retirement protocols are otherwise unchanged. Full failed-removal recovery in that direct reader binding remains a separate open boundary; this unit does not establish that every reader/sidebar teardown is accepted.
