# Archive selection and download ownership

Baseline: `dd87555c49a43c779ab8a36f954eed916f8fd5eb` (2026-10-08).

## Request and presentation lifetimes

ArchiveDownloadDialog captures its application, window, navigator, route and input generation. Retained expansion, selection and confirmation callbacks require that original generation and current-route admission. Replacing the comic, downloader or host clears the old choice and cancels its request scope. Accepted work remains registered with its original hosts until the existing source completion bridge really settles, including real QuickJS rejection or resolution after removal. Registration precedes arbitrary source invocation, covering synchronous host closure.

Each accepted list/link read uses the existing RequestScope.runToCompletion contract. Cooperative cancellation does not stand in for the accepted callback's completion. A source failure that finishes after cancellation retains its existing Res/FailureDetails result; the normalized message and original stack are logged even when presentation is no longer permitted. These optional reads do not turn a source/network error into a fatal application-close error. No universal task queue, new downloader or source protocol is introduced.

List completion updates only the same input's own view. A successful link obtained while covered is retained for an explicit confirmation after that route becomes current again; it does not pop the covering route or automatically rerun the source callback. Changing selection discards that retained link. Normal download still bypasses link lookup and can be selected while the optional list is pending; successful route exit cancels that list immediately while its original hosts continue waiting for real completion. Retry, option order, duplicate/empty source IDs and link trimming remain with the existing helpers and source parser.

showArchiveDownloadDialog owns its exact ResourceDialogRoute through WindowSelectionTask. Whole-Navigator disposal completes it even before the first widget build. Failed removal ends its presentation wait with the failure while retaining the exact route for explicit close retry. Back/barrier return null; Normal returns the existing normal selection. The root navigator, captured themes, barrier color, labels and main content layout retain the previous showDialog behavior. An expanded replacement with no active read offers Retry rather than an indefinite spinner.

ComicPageActions.download uses this presentation and rechecks the original host and comic before queue publication. Its original source/library snapshots, duplicate-choice guard, duplicate-download check and existing task constructors remain. Application/window closure or another route becoming current cannot publish an old accepted choice. Other action methods and the chapter-selection widget are unchanged. The ordinary chapter sidebar's own lifetime/retained controls remain a separate unfinished boundary; the additional caller admission checks do not establish its full acceptance.
