# Issue 分类与诊断采集

English: [Issue reporting and diagnostics](issue_reporting.en.md)

从 [新建 Issue](https://github.com/CyrilPeng/Venera-Next/issues/new/choose) 选择实际出错的功能。一个 Issue 记录一个独立问题；同一问题涉及多个平台时在同一报告中注明区别。标题写清触发条件和症状，例如“批量归档到 WebDAV 后部分文件上传失败”。

本仓库维护应用本体，包括本地阅读、扩展运行时、下载、网页登录和 WebDAV。具体源站内容、作品可用性和第三方源脚本应反馈给对应维护者。提到漫画源不代表一定超出范围，请说明应用侧异常的依据。安全漏洞使用[安全政策](../../SECURITY.md)中的私密反馈方式。

## 选择入口与必要材料

| 入口 | 适用情形 | 必要材料 |
| --- | --- | --- |
| 崩溃、启动失败或无响应 | 进程退出、无法启动、整个界面持续无响应 | 出错时段的应用日志、系统崩溃或原生启动日志 |
| 阅读卡顿、慢加载或内存异常 | 图片出现慢、首次／回看停顿、阅读掉帧或内存异常 | 实际采集的“阅读诊断”报告或摘要；普通日志或只有录屏不能替代 |
| 本地导入、导出与数据异常 | 导入导出、导入成功但不显示、收藏／历史保存、备份恢复异常 | 出错时段的应用日志；操作入口、匿名文件结构和真实结果 |
| 下载、网络与 WebDAV 故障 | 下载、CBZ 归档上传／下载、应用数据同步、在线库或网页登录失败 | 出错时段的应用日志；具体操作、错误／HTTP 状态及逐项失败阶段（如有） |
| 界面、操作或其他应用缺陷 | 布局、导航、焦点、阅读操作、扩展运行时或暂不能归类的缺陷 | 纯界面问题不强制日志，需步骤和可选截图；扩展运行时和其他缺陷需日志 |
| 功能建议 | 尚未提供的行为与改进 | 场景、方案、主要功能／适用平台及可观察的验收标准；不要求日志 |

所有需诊断的类型均允许“无法取得”路径，但需具体原因和替代证据。归档失败、导入后不显示应选对应功能；只有进程退出或持续无响应才属于崩溃。不要为了绕过日志要求选择界面类型。

缺陷报告统一要求具体版本／构建号及手机／TV 等安装包类型、平台、设备与系统版本、复现步骤、预期与实际行为。自编译包可填 `commit <提交号>`。不要只填“最新版”“有问题”或“稍后补充”。偶发问题可描述最后一次的发生时间和现场，不要求反复制造崩溃。

## 应用日志

1. 在原有环境中复现一次，记下大致时间和操作。已有对照无需重做，不清缓存、清库或重新导入整套数据。
2. 尽快进入 **设置 → 日志 → 更多 → 导出**，得到 `log.txt`。级别筛选只影响页面显示，导出包含本次运行保留的内存记录。
3. 检查后粘贴出错时间附近的片段与调用栈，或拖入脱敏后的 `.txt`、`.log`、`.json` 附件；较大文件可压缩为 `.zip`。确认上传完成再提交。
4. 保留时间、错误类型、状态码和阶段，移除账号、Cookie、Token、签名 URL 参数、私人标题及完整个人路径。第三方扩展输出仍需人工检查。

页面最多保留 500 条记录，重启不会把上次会话重新载入页面。需要上一轮日志时，在已有访问权限允许的范围内检查应用数据目录的 `logs.txt` 和 `logs.previous.txt`。Windows 常见目录为 `%APPDATA%\com.github.cyrilpeng\VeneraNext\`，自定义／迁移路径以实际目录为准；移动平台无需获取 root 或更改系统授权。详见[磁盘日志](../development/logging.zh.md)。

默认的单条长度限制通常足够。仅在明确需要完整错误响应且可安全脱敏时，才临时选择“禁用长度限制”。不提交完整备份、数据库或私人漫画代替日志。

## 阅读性能诊断

`v1.18.2` 正式版及更新的已发布版本提供此入口；首次含入口的候选版是 `v1.18.2-rc.6+242`，更早版本可能没有。

1. 保留模式和设置，用少量已下载的图片从原来的本地入口阅读。若只在 WebDAV／扩展入口发生，注明区别，不为采集下载整部漫画。
2. 阅读器菜单 → **阅读诊断 → 开始新的 45 秒采集**；关闭说明窗口后按最短步骤复现。已有首次／回看对照直接描述，不要求重复。
3. 再次打开诊断，停止、预览，并在退出阅读器前**复制报告**。报告仅在当前阅读器内存中，退出清除，不自动上传。
4. 粘贴 JSON 或上传 `.json`／`.txt`。可只保留 `imageEvents` 之前的摘要，包括 `configuration`、`durationUs`、`retainedFrameSamples` 和 `retainedStageSamples`；事件明细截断无需重贴。
5. 说明阅读模式、内容入口、图片格式／尺寸范围、刷新率、图片处理开关，以及图片出现慢还是整个界面停住，不附标题、地址或脚本正文。

阶段异步等待不是 CPU 耗时，帧样本也不是整段实测 FPS。未开始采集的预览不是报告。旧版没有入口或无法完成采集时走“无法取得”路径。详细说明见[阅读器短时诊断](../development/reader_diagnostics.md)。

## 无法启动或无法取得诊断

选择“无法取得”，在日志字段写明无法取得，并填写：

- **日志无法取得的原因**：尝试的入口和具体阻碍，例如“点图标立即退出，无法进入设置；检查常见目录后未找到启动日志”。只写“不会导出”“没有日志”或“稍后补”不满足要求。
- **替代证据**：脱敏错误截图、系统错误／安装日志，或包含发生时间、失败阶段、复现频率的具体现场说明。

Windows 在 Dart 初始化前记录 `%LOCALAPPDATA%\com.github.cyrilpeng\VeneraNext\logs\windows-startup.log`，可能有 `windows-startup.previous.log`。该路径与应用日志不同；缺少 DLL 等加载错误可能早于日志生成，此时保留系统提示即可。详见[Windows 启动诊断](../distribution/windows.zh.md#启动验证与诊断)。

Android／iOS／鸿蒙可提供系统已有的崩溃提示、安装错误或应用专属诊断；不要求完整设备日志、root／越狱、降低系统安全设置或上传签名密钥。没有现成系统日志时，详细现场说明仍是允许的替代证据。

## 提交后的检查

表单阻止必填项为空，固定规则进一步检查分类、占位回答和日志／报告引用，不需要 AI API 或 Secrets。新建、编辑、重新打开 Issue 以及新增／编辑／删除评论均会复查。

缺项会加上 `needs: information` 并在同一条机器人评论中列明；补齐后更新原提示并移除标签。报告者可在评论中补日志／报告，维护者证据也可使用，普通旁观者或机器人评论不算诊断证据。

机器人管理 `bug`／`enhancement`、主要 `area: …` 和 `needs: information` 标签，保留人工调查／计划／等待新版反馈等状态。不会自动关闭或重新打开，也不追补旧格式报告；已有报告沿用原跟进和验收安排。

GitHub Forms 无法随下拉项动态改变另一字段是否必填。四个诊断入口直接把诊断字段设为必填；界面入口中的扩展运行时／其他缺陷及“无法取得”时的两项补充，由提交后校验。文字或附件引用存在不代表内容有效，机器人不会下载附件或替代维护者诊断，也不能可靠识别故意选错类型的报告。
