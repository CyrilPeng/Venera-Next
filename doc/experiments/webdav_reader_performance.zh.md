# WebDAV 阅读卡顿分阶段排查（#125）

## 现有证据与边界

反馈描述 Android 在分页、条漫、瀑布流加载下一张 1500×2400 图片时卡顿，下载到本地后仍然发生。它提示应检查共用图片管线，但不能据此认定是网络、解码、去混淆或某个阅读模式的根因。

2026-10-28 已[请求核对版本与最小对照信息](https://github.com/CyrilPeng/Venera-Next/issues/125#issuecomment-6462490650)。报告填写 `1.18.2-rc2`，回复时最新官方候选包为 `v1.18.2-rc.1+237`；需要先确定安装来源和完整构建号。图片格式、机型、图片处理设置，以及“图片出现慢”还是“整个界面掉帧”也尚未明确。没有下载私人漫画、日志附件或备份。

本轮没有 Android 设备连接，没有复现原报告的设备卡顿，也没有修改运行时缓存、并发、缩小解码或网络策略。#125 保持开放，不能算作候选版已修复项目；#91 的发热耗电仍是单独的验收范围。

## 可复现宿主探针

`tool/reader_decode_probe.dart` 生成同一组彩色合成像素的 PNG 和 JPEG，默认尺寸 1500×2400。每种格式分别测试本地文件读取和已在内存中的编码字节，各预热一次、记录五次。

```powershell
flutter test --no-pub --reporter expanded tool/reader_decode_probe.dart
```

使用仓库指定的 Flutter 3.41.4。可通过 `--dart-define=READER_PROBE_RUNS=10` 调整次数，或使用 `READER_PROBE_WIDTH`、`READER_PROBE_HEIGHT` 指定合成图片尺寸。只在忽略的 `build/reader-decode-probe/run-*` 内生成测试文件，不访问用户数据或网络，不需要私人输入。

本地字节读取调用生产 `ReaderImageProvider.load`，在测试进程内临时关闭自定义图片处理，结束后恢复。后续使用 Flutter 的 `ImmutableBuffer`、`instantiateImageCodecWithSize` 和 `getNextFrame` 入口分阶段计时，核对读取字节与解码尺寸并释放图像和 codec。生成、写盘及结果校验均不计入耗时。

**这个探针刻意不挂载阅读器，不经过完整 provider 生命周期或 Flutter ImageCache。** `encoded-memory` 表示重用编码字节后再次解码，不是已解码图像缓存命中；本地文件重复读取也不能被称为真实冷磁盘读取。异步首帧等待时间不等于 UI 线程阻塞时间。

## 2026-10-28 宿主结果

Windows x64、Flutter 3.41.4、Dart 3.11.1，`flutter test` 宿主模式。每组五次的中位数，单位 ms：

| 格式／输入 | 本地读取 | 首帧解码等待 | 读取至首帧总耗时 |
|---|---:|---:|---:|
| PNG／本地文件 | 1.77 | 43.17 | 45.26 |
| PNG／编码字节 | 不读取文件 | 43.42 | 43.77 |
| JPEG／本地文件 | 3.12 | 68.30 | 72.09 |
| JPEG／编码字节 | 不读取文件 | 69.00 | 69.77 |

原始 20 组结果见 [JSONL](data/reader_decode_windows_20261028.jsonl)。这组合成 PNG 为 120,499 字节，JPEG 为 2,424,487 字节；二者来自相同像素，但编码内容和压缩特征不同，不能用此表推导所有 JPEG 比 PNG 慢。单张完整 RGBA 像素为 14,400,000 字节，不包括缓存、纹理和其他内存，不能当作进程总内存。

本机合成样本中，字节已在内存仍需要首帧解码等待。它说明“下载完成”不等于“显示无需解码”，但不证明 Android 上发生了 UI 掉帧，也不证明 #125 的根因。不能将宿主测试耗时换算成真实 FPS，或拿它与 Mihon 的设备表现直接比较。

## 下一轮设备验收

1. 确认原包完整版本／构建号、机型系统、图片格式和处理设置；保留已有文件与配置，不要求清库、清缓存或重新下载整部。
2. 使用合法可控的同一组图片，分别从在线库、完整下载后的离线入口和纯本地导入入口阅读；核实离线场景确实没有退回网络读取。
3. 对分页、连续、瀑布流分别记录首次读取、翻回刚看过的页面和跨章；固定预加载、缩放、图片处理、刷新率与缓存设置，区分编码字节复用和已解码图像命中。
4. 在 Android profile／release 包上记录 UI／raster 帧耗时、图片读取／解码、GC 和峰值内存；性能采样使用 profile 工具，不能将普通 widget 测试时钟当作真实帧统计。避免上传账号、签名地址和完整私人日志。
5. 只有稳定复现并定位后才选择改动；缓存必须有界，不以无限保活、取消资源收尾、默认降低画质或盲目增加并发换取表面改善。加入对应回归后再邀请原设备复测。
