# 漫画 OCR 翻译与外挂字幕方案

**设计草案 v0.1 · 2026-11-26**。面向阅读器维护者和桌面字幕工具作者。草案号用于评审本文，交换格式将独立编号。目前完成了三页手工校对稿与 ACBF 1.1 的往返实验，阅读器接入和真机验收列在后续里程碑。

## 读者要完成的事

读者在电脑上给一章漫画识字、翻译、校对，将字幕单独传到已有同版漫画的手机。手机断网后可以切换原图与译文，输入原文或译文中的一句话，回到那一页并看见对应的气泡。对于本来就能读懂的中文漫画，读者可以在识字后直接获得台词搜索。

首版以本地图片目录和 CBZ 的导入、再导出为入口。桌面生产字幕，手机和桌面负责阅读。验收时保存原图、关闭字幕或导出普通 CBZ，原页面文件的 SHA-256 应与导入时一致。局域网按页调用 OCR、在线漫画源挂载、WebDAV 字幕传输、全库搜索和朗读按后续需求推进。

## 字幕如何生产和校对

| 环节 | 读者或制作者的操作 | 中间结果和恢复方式 |
| --- | --- | --- |
| 识字 | 选一章和原文语言，使用桌面 PP-OCR、外部 OCR 工具或手工录入 | 每页保存原图绑定和逐框识别结果。无字页记为“未检出文字，可复查”，服务出错记为“失败，可重试”。只有原文也可导出。 |
| 分组 | 把同一气泡的竖列合成一句，必要时拆开相邻气泡，调整对白顺序 | 保留输入框和原始识别文字。对白有独立身份。移动文本框、修改错字、改译文沿用原身份。真正拆成两句或合并多个已发布对白时，记录旧身份与新身份的对应，提示复核已有定位。 |
| 翻译 | 选择目标语言，按阅读顺序成页发送对白，可带本作品的人名术语 | 按对白 ID 接回译文，只写入唯一匹配的结果。缺句、重复 ID 或未知 ID 标记到对应批次复核。保存已识别原文，可只补译失败段或新增语言。 |
| 校对与发布 | 并排看原图、原文、译文，跳到低置信度或待确认处 | 人工确认的文本优先。重跑 OCR 或翻译产生候选差异，由制作者选择覆盖。写到临时文件、验证完整后替换，保留上一份可读版本。 |

首个生产端可用独立桌面工具读取用户选择的原图，也可接入“屏译”的相册分段结果。其分段已有原文、译文、原始小框、整段区域和方向，页面记录同时保存原尺寸与处理尺寸。适配时应把识别坐标还原到正向原图，并由作品级编辑流程分配持久身份。当前样例中的识别框由手工标注。模型评估应记录每页耗时、错误合并或拆分数、阅读顺序错误数及人工校对用时。[屏译分段结构](https://github.com/ciddwd/overlay-translator/blob/64a7aa2c9605c88dd35bdeea42ab5c0f1c18ce5e/app/src/main/java/com/gameocr/app/gallery/GalleryTranslationModels.kt#L48) · [页面尺寸和存储](https://github.com/ciddwd/overlay-translator/blob/64a7aa2c9605c88dd35bdeea42ab5c0f1c18ce5e/app/src/main/java/com/gameocr/app/gallery/GalleryTranslationDatabase.kt#L66)

## 一份字幕需要表达什么

| 对象 | 两个独立实现应能取得的同一结果 |
| --- | --- |
| 作品与版本 | 标识这套页面所属的作品和版本。应用内漫画 ID、源站 URL、设备绝对路径只能用作本地提示。 |
| 章节与原图页 | 记录章节、原图顺序、在本版本内持久的页 ID、正向宽高及页面内容摘要。文件名、相对路径、序号帮助找候选，文件摘要用来核对绑定。 |
| 对白与阅读顺序 | 每个对白有稳定 ID、所属页、显式次序和原图区域。原文可含多个识别框，译文可换行或另设布局区域。一个气泡跨显示切片时仍只算一句。 |
| 文本与修订 | 区分原始识别稿、校对原文和带语言标记的译文。原文语言和目标语言分开保存，允许只有原文、多个语言或同语不同译本。检索和朗读使用选定版本的文本。 |
| 可选表现 | 可给出遮罩、排版方向、底色及字号建议。基础阅读至少支持原文、译文和准确的定位。局部透明背景补图作为后续可选资源，校对文本可单独替换。 |

坐标以**应用 EXIF 方向后的完整原图**为基准，原点在左上，横向向右、纵向向下。实验以原图像素和宽高记录区域，矩形采用左上包含、右下排除的边界。若另一种交换表示使用归一化坐标，在读入时统一换算，导出时从原始精度计算。原图换了裁幅、旋转烘焙方式或源脚本改变页面几何时需要重新核对。坐标与字流方向独立，竖排原文可以配横排译文。

## 同一页如何在另一台设备上找到

首个绑定策略以**原页面文件字节的 SHA-256**提供精确匹配。它能跨改名、重新排序和无损打包。相同画面重新编码也会改变字节，需转入人工复核。摘要计算在导入或用户挂载字幕时后台进行，按章记录进度。重复打开优先使用已核验的绑定，源文件改变时重新核验。

| 漫画或字幕的变化 | 阅读器预期行为 |
| --- | --- |
| 解包后改名、各章展平、再导回 CBZ | 优先在指定版本与章节中按摘要寻找唯一候选，更新本地位置。源文件名或显示页码改变也能跳回原对白。 |
| 插页、缺页、同名同尺寸的另一扫图 | 只显示已核验的页，列出未匹配页供逐页预览。读者仍可看原图和已确认的字幕。 |
| 同一章有两张字节相同的回忆页 | 保留两个候选。用已绑定的页 ID 或制作者保存的页序清单消除歧义，仍有歧义时请求选页。 |
| 替换字幕或重新校对 | 以版本、页和对白的持久身份重建受影响的索引。一次导入失败保留旧文件与旧索引，撤下字幕后清理对应索引。 |

现有 CBZ 导出会把分章图片展平并按顺序重新命名。后续接入需让导入、导出显式处理字幕，并在归档写出前更新随包的相对引用。独立传输和嵌入归档共享同一种字幕内容，传统阅读器应仍能浏览原图。[现有 CBZ 导出](../../lib/features/local_comics/import_export/cbz.dart)

## 阅读、搜索与显示

阅读器把原图上的对白区域与本页实际绘制的源矩形求交，再复用图片的裁边、切片、缩放及平移变换。画廊单图与同屏多图分别验证，连续及瀑布流按真实原图页绑定。双页中缝上的对白应高亮两个可见部分，搜索只返回一次。译文放不进某个切片时，显示可点标记和完整文本。普通白底气泡可原位覆字，网点和人物脸部优先保留画面、以标记查看。先显示原图，异步字幕只更新可见区域。[原图与切片](../../lib/features/reader/image_position.dart) · [画廊](../../lib/features/reader/gallery_view.dart) · [裁边与拆页绘制](../../lib/features/reader/comic_image.dart)

本书搜索同时查校对原文和选定译文。同一对白双语都命中时合并为一项，显示章节、原图页和命中片段。点选后先加载目标章，再把原图序号映射到当前布局，等待实际图片几何就绪，滚至目标框并短暂高亮。换源或退出时取消旧定位。长条的验收条件是**下方气泡进入视口**。进度沿用阅读器实际可见位置的记录方式。[页码换算](../../lib/features/reader/page_layout.dart) · [章节加载](../../lib/features/reader/chapter_loader.dart) · [历史映射](../../lib/features/reader/history_progress.dart)

初版可按书、页维护可重建的本地索引，保留原文字形供显示，另存 Unicode 规范化后的搜索文本。先用一至两个字的人名、日文原句、英文大小写和校对后的译名做子串检索验收，再在万句级样本上比较朴素检索与 SQLite 全文索引。索引按字幕修订更新，支持撤下字幕和重建。

接入时，格式解析器输入字幕字节，输出页、对白和资源引用，方便桌面工具复用。应用负责把页绑定到本地书库并保存索引。阅读器按“当前章＋原图页”请求可见对白，搜索命中后传入同一套页和区域地址。归档模块只在导入／导出时发现、校验和搬运字幕资源。这样，替换 OCR 服务无需变更文件读取或原图绘制代码。

## ACBF 互通与格式选择

ACBF 1.1 定义了页面图像引用、分语言文本层、有序文本区域和像素多边形。官方《Craphound》1.1 样书的 23 页都有英语和斯洛伐克语文本层，两种语言的框和次序在该样书中逐页对应。其他作品可能一对多或需要挪动译框。外部图像引用可以与字幕一起放在 CBZ，适合验证单文件传输和整书打包两种入口。[ACBF 正文规范](https://github.com/ACBF-Advanced-Comic-Book-Format/ACBF/wiki/Body-Section-Definition) · [官方样书](https://github.com/ACBF-Advanced-Comic-Book-Format/ACBF/tree/e033e004e2897fe20ad09cbd649a8ba1d6b38d09/Sample%20Comic%20Book)

本次实验以同一份《山路》校对稿生成 ACBF 文本层，和独立编写的示例逐段核对，再以外置 PNG、改名重打包的 CBZ 读回。原文、译文、顺序、坐标都能保留。仅修改持久对白 ID、原始 OCR 小框、校对状态和书写方向时，基础映射产生相同 XML。这些差异需要明确定义如何交换。换页匹配和跨缝几何已用样例计算，Flutter 的视口定位与手势仍待原型实测。[试验材料与复现命令](../../spec/comic-subtitles/README.md)

**格式决策保持开放到第一次独立互通评审。** 优先试用 ACBF 作为基础阅读表示。如果跨语言多对一、持久页绑定及修订能通过明确的兼容约定无损往返，记录这组约定及旧读者的表现。如果需要伴随清单，验证它与 ACBF 如何绑定、单独丢失时如何显示。如果两个独立实现仍会失去对白身份或错配页面，再评估独立 sidecar 格式并保留 ACBF 转换。评审记录逐字段列出“无损、需约定、会丢失”及实际样本，同时决定主扩展名、媒体类型和必要的校验文件。

## 平台、隐私与失败恢复

- **阅读端**消费已经生成的字幕。移动端打开一章时可完全断网，直接阅读和搜索。字幕开关只更新显示层，复制／保存原图走现有缓存与导出路径。TV 遥控焦点、无障碍阅读顺序、大字号文本面板及暗色背景需单独检查。
- **生产端**默认由用户发起任务，按页保存并支持取消、恢复和单页重试。连接局域网电脑或云服务前显示接收方与发送内容。仅需文本翻译时发送选定对白和用户勾选的上下文，图像 OCR 单独授权。密钥保存在设备，日志仅记录阶段、计数和耗时。评估模型时另行核对权重许可与分发条件。
- **导入端**把字幕和附带资源视作数据。只解析用户选定文件或归档内的相对资源，使用关闭 DTD、外部实体和远程资源加载的 XML 读取器。复用归档路径检查，为解压总量、页数、区域数、文本长度和补图解码像素设限。边界值通过样本压测确定。错误包含页和原因，导入中断可回到上一个完整版本。
- **WebDAV 与无头命令**属于后续接入。应用数据同步、漫画归档和 NAS 在线书库已有各自的配置。若增加字幕同步，应定义字幕目录、版本冲突和凭据范围。桌面独立生成工具可直接读取用户给定的文件，新无头命令另需考虑应用数据目录占用。[应用数据同步](../user/data_sync.zh.md) · [无头模式](../user/headless.zh.md)

## 独立维护与迁仓

规范的孵化根目录是 `spec/comic-subtitles/`。保存在里面的对照样例、复现命令和未来的格式正文都能脱离 Flutter 仓库使用。阅读器的 Dart 适配、UI 状态、索引实现、平台工作流及本方案留在应用仓。外部作者可以用任意语言实现测试样例。规范正文作为交换语义的唯一发布入口，App 文档引用相应版本。

孵化期由维护者评审。改变文件含义的提案需写明真实用例、旧读者行为、迁移方式，并增补正反样例。可选表现能力允许旧读者降级到基础文本；影响页身份或几何解释的未知必需能力应提示版本不兼容，保留原文件供新版使用。编辑器遇到不能无损保留的扩展时可只读打开。历史版本按原样保留，固定版本的样例与校验文件可离线使用。

当外部生成器与 VeneraNext 完成上一节的独立互通，可在 1.0 之前拆仓。迁移清单包括目录历史、作者署名、许可和样本来源、已发布版本、测试向量与变更记录。旧入口保留索引并指向新仓，后续由标准仓发布版本，应用固定到相应版本。候选标签采用 `comic-subtitles-v0.1.0` 这类前缀，以避开应用的 `v*` 发包规则。公开接收贡献前明确规范、校验代码、样图三者的授权。建议分别考虑 CC BY 4.0、Apache-2.0 和可再分发的原创素材许可，最终由权利人确认。现阶段沿用主仓现有许可，第三方材料只链接出处。[完整构建工作流](../../.github/workflows/main.yml) · [仓库许可](../../LICENSE)
