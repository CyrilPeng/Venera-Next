# 本地归档导入后不显示：#115 排查记录

## 当前结论与验证边界

- 2026-10-29，作者报告 iQOO Neo5 / Android 14、realme Neo5 SE / Android 16、Redmi Note 9 Pro / Android 12 仍复现；随后确认实际使用的是 v1.18.1 正式版（截图显示 `V1.18.1`，未单独显示构建号），分别单个导入与批量导入都会出现。该版本不包含 v1.18.2-rc.1 起的隐藏数量提示，也不包含本轮选择修复；不再重复索要已经收到的版本、设备与导入入口。
- 截图处于多选模式，左上角数字是 `selectedComics.length`，不是导入成功数量，也不是独立的数据库行数证据。不能仅凭它确认入库成功或把根因归于屏蔽词。
- 已独立复现并修复本地列表的选择范围问题：全选／反选错误纳入被关键词过滤的记录；查询生成新的 `LocalComic` 对象后，旧选择失去卡片高亮；删除或过滤选中记录后仍残留旧选择与计数。
- 修复只约束选择范围并重新绑定当前可见的漫画身份，不改变归档名称、解压策略、数据格式或关键词规则。过期的批量菜单与删除确认不能继续操作失效的选择。
- **没有证据将上述选择问题等同于作者 Android 上的完整“不显示”根因。** 不关闭 #115，不把已通过的 Windows 或模拟通道测试称为 Android 真机验收，不要求清库或自动改名。

## 自动化回归

`test/features/local_comics/local_archive_visibility_test.dart` 使用自行生成的有效 PNG / JPEG，创建内容完全相同、名称不同的两个 ZIP，不包含用户附件或私人图片。

覆盖以下完整的 Dart 消费链：

1. 本地文件、模拟 Android 可直接读取的文件、模拟 Android 需临时复制的文档，以及目录批量归档导入。
2. 短名称与带多段点号、长标题、双扩展名的名称同时存在；正反两个输入顺序。批量用例改变文件创建顺序，但不把宿主文件系统的枚举顺序当作保证。
3. 真实归档解压、不同 ID／输出目录的入库与查询、375 px 手机布局下两个卡片的显示、全选，以及关闭／重新打开数据库后的同样检查。
4. 实际读取并解码导入后的封面及 PNG / JPEG 页面，检查原始 ZIP 字节不变；移动列表卡片使用内存图片以隔离宿主异步文件句柄，不能代替 Android 的封面 I/O 验证。
5. 有意设置关键词后，仅选择可见条目；屏蔽规则变化、数据库通知和移除记录及时维护选择；过期菜单与已打开的删除确认不删除／导出隐藏条目。

基础 13 项用例中，修复前 8 项双归档对照通过、5 项选择回归失败；修复后均通过。另补充过期菜单、删除确认、挂载期间导入第二份归档，以及明暗主题、横竖屏、大字号／减少动画用例。

作者说明其屏蔽词与某类题材相关，但未给出具体命中词；不能因此认定不会匹配普通标题，也不能断言已确认其设置。另用合成归档验证 `bl` 会命中标题里的 `black`，大写 `BL` 不匹配小写 `black`：现有规则是区分大小写的字符串包含匹配，不识别图片内容或题材。此项只记录诊断线索，保留规则，不擅自替用户更改关键词。新增回归共 21 项。

`test/native/selected_file_storage_test.kt` 直接测试生产 `SelectedFileStorage` 的名称保留、独立复制所有权和重新打开后的释放，包括空格、括号、Unicode 破折号与双扩展名。

**模拟的部分**：Android `prepareFile` / `releaseFile` 的 MethodChannel 返回值和临时复制。它不调用 Android `ContentResolver`、真实 DocumentsProvider 或 Android 版原生 ZIP 解压库。Kotlin 独立 JVM 测试也不是 Android 设备测试。

本轮在忽略的 `build/issue-115-20261029/avd` 内配置了独立 Android 14 / API 34 AVD，未使用日常设备或应用数据；两次启动虽报告 guest boot completed，但 ADB 均无法连通，已停止实验进程。因此没有取得 Android APK 的安装／运行验证，不以模拟器启动日志作为应用测试通过的证据，不修改系统代理／防火墙或其他设备设置来绕过此限制。

## Android 复现与验收清单

优先在可用的 Android 12 / 14 / 16 设备或模拟器中，用合成归档完成以下检查；原设备结果仍以作者反馈为准。

1. 记录完整版本、构建号和安装来源，区分正式版与 RC；v1.18.2-rc.3+239 首次包含本轮选择修复及 #125 的缓存键修复，v1.18.1 和此前 rc.1／rc.2 不包含，不要求反复安装同一个旧包验证未交付的改动。
2. 同一合成 ZIP 分别命名为短标题与多段点号／双扩展名的长标题，分别单个导入，再在独立测试数据中对照批量入口及反向导入顺序。保留原文件，不在日常库中重复大量导入。
3. 分别核对导入结果、按漫画身份关联的数据库记录、列表可见数量与隐藏提示；退出多选再观察列表。多选标题数字不能替代这些证据。
4. 在默认存储位置对照系统文档选择器的直接读取与临时复制分支；必要时再单独检查自定义 SAF 存储位置。记录是哪一步出现差异，不预设权限或文件名是根因。
5. 检查每一条目的封面、页面读取以及进程重启后的显示。若记录存在且没有被筛选，但卡片仍不显示，再关联 UI 构建异常和对应身份；若记录不存在，回到准备／解压／注册阶段检查，不只修改列表。
6. 屏蔽一个合成标题后，全选／反选不得选中隐藏项；移除屏蔽恢复两个卡片，不自动恢复此前已清除的选择。筛选在删除确认打开后变化时，旧确认不得继续删除。

只记录必要阶段、匿名化漫画身份和计数。公开反馈不需要私人漫画、完整数据库、账号、Cookie、Token、签名链接或完整个人路径。不要把网络连通失败当作无人反馈，不因观察期结束或仅有合成回归通过就关闭此 issue。
