# 漫画 OCR 翻译与外挂字幕分阶段实施方案

2026-11-27 · 测试分支 `test/comic-subtitles` · 起点 `5122f518`（当日 `origin/main`）

第一个可交给读者的版本，要能在断网的 Android 手机上给本地漫画挂载字幕，按原文或译文找到一句话，并把对应气泡滚入视口。先用已经校对的《山路》验证这一段体验。接入真实 OCR 后，再用同一套阅读验收判断问题出在识字、翻译、页面绑定还是绘制。[设计草案](comic_subtitles.zh.md) · [三页样例及预期结果](../../spec/comic-subtitles/README.md)

在仓库根目录运行 `python spec/comic-subtitles/check_examples.py` 可复现十项离线检查，涵盖 ACBF 往返、两版清单、OCR 校对版整章、拆页几何及五个反例。设备试用与人工试读采用同一份[《山路》0.1 校对版 CBZ](../../spec/comic-subtitles/fixtures/mountain-path-0.1.cbz)。[阶段 1 挂载回归](../../test/features/reader/subtitle_mount_test.dart)

| 阶段 | 从哪里开始 | 交付物与通过条件 |
| --- | --- | --- |
| 1 · 页绑定与挂载 | 三页手工稿、同版图片目录和 CBZ | 能挂载、替换、撤下字幕。改名能匹配，同图多页能复核，失败能继续读旧版。 |
| 2 · 离线阅读与搜索 | 阶段 1 的已绑定页 | 手机断网完成切换、双语搜句、跨缝高亮和长条定位，保存的原图摘要一致。首个读者测试包在此产出。 |
| 3 · 桌面 OCR 与校对 | 阶段 2 的读者测试包 | 在 Windows 处理一章，校对识别结果后导出纯原文字幕，在手机上检索到校对后的气泡。 |
| 4 · 翻译与修订 | 阶段 3 的校对稿 | 按对白 ID 补译、审校、重新发布。失败批次可重试，已确认的对白可追溯。 |
| 5 · 格式互通与归档 | 阶段 2 的 Dart 读取器和阶段 4 的桌面生成器 | 两个独立实现交换同一章，完成字段核对及 CBZ 往返，作出格式和拆仓决定。 |
| 6 · 多端试用与合入 | 通过互通的候选版本 | Android 手机、Windows 和低内存设备有可复核的功能及性能记录，可以决定合入范围。 |

## 1 · 让字幕可靠地找到原图

本阶段按三个可单独评审的改动实施。

1. **读样例。** 增加只依赖字节输入的 Dart 解析器，用 ACBF 读出正文页、语言、文本区域和顺序。用现有 `dialogues.json` 作测试对照。为本轮原型生成实验清单，显式关联 ACBF 文件摘要、页 ID、原图摘要、对白 ID 与各语言区域。现有样例的基础 ACBF 会丢失对白身份和校对信息，公开格式留到阶段 5 选择。
2. **绑原图。** 在读者选定的本地漫画和章节内，后台计算页面**原始文件字节**的 SHA-256。唯一匹配写入本机绑定，同摘要的两页保留两个候选供预览。嵌图 ACBF 可从内嵌字节取得摘要。只有相对图名且缺少可信摘要时，请读者核对页面。文件名和章内原图序号用于找候选，重开书复用已核验的绑定，替换原图触发复核。[本地章节加载](../../lib/features/reader/chapter_loader.dart) · [归档页面规则](../../lib/features/comic_storage/comic_file_rules.dart)
3. **接挂载入口。** 在默认关闭的实验开关后，为已导入的本地目录漫画和 CBZ 漫画提供选择字幕、查看匹配结果、替换和撤下操作。只读选定范围的本地资源，关闭 XML 的 DTD、外部实体和远程引用。对资源总量、页数、区域数和解码像素设限，并为上限及超限各留用例。先校验新修订和绑定，再一次切换生效版本。撤下只清理本机绑定及其派生索引，保留用户的字幕文件。

**验收**　用同一章依次测试改名重排、插入重复页、替换成同尺寸异图和中断字幕更新。记录每页为已匹配、待选择或缺失。重复或失配页仍可看原图，损坏清单或中断后重开仍可用上一版。把独立样例检查接入 PR 作业，分别为解析结果、候选页和替换失败写回归。

## 2 · 在离线手机上读到并找到一句话

阶段 2 的候选版本提供字幕开关、语言选择与本书搜索。组件回归用 200 像素的视口验证长条页底部气泡实际进入视口，原图导出与导航另跑现有回归。Android 飞行模式及低内存设备的数据待测试包实测。[阅读回归](../../test/features/reader/subtitle_reading_test.dart)

阅读层按“章＋原图页”取对白。坐标统一到应用 EXIF 方向后的完整原图，复用实际绘制的裁边、拆片、缩放和平移变换。先绘制原图，再更新可见字幕。读者可切换原图与译文，复杂背景或窄切片上可点标记查看完整文字。保存、复制原图继续使用阅读器的原图导出入口。[原图身份与切片](../../lib/features/reader/image_position.dart) · [绘制](../../lib/features/reader/comic_image.dart) · [原图导出](../../lib/features/reader/image_export.dart)

按书和字幕修订建立可重建的子串搜索索引，索引校对原文及选定译文，用对白身份合并双语命中。点选结果先加载目标章，再将原图序号换算成当前布局页，等待图片几何就绪后滚动并高亮。换章、退出或选择新结果时取消过期定位。用例覆盖单页、同屏多图、连续模式、跨章瀑布流和返回续读。[显示页换算](../../lib/features/reader/page_layout.dart) · [视口绑定](../../lib/features/reader/reader_viewport.dart) · [历史进度](../../lib/features/reader/history_progress.dart)

| 飞行模式下的操作 | 通过条件 |
| --- | --- |
| 在三页样书分别搜原文 `山の下` 和译文 `脚下` | 两次都定位第一页的 `ridge-foot`。缩放、平移及切换字幕后，文字仍对应同一气泡。 |
| 搜 `入口`，分别以左半、右半优先拆页 | 结果只有一条。跨中缝的 `gate-entry` 在两片各有一处可见高亮，次序切换后仍对齐。 |
| 在可视高度小于长条的窗口搜 `日出` | 第三页下方的 `dawn-sunrise` 进入视口。只跳到第三页顶部算失败。 |
| 替换字幕、撤下、重开普通漫画并保存原图 | 搜索采用当前修订，撤下后旧命中消失。翻页、手势和续读通过原有回归，保存的页面 SHA-256 与输入一致。 |

## 3 · 桌面识字与人工校对

Windows 实测使用 Python 3.11.18、RapidOCR 1.4.4、ONNX Runtime 1.32.0、包内 ch_PP-OCRv4 det/rec 权重和两条 CPU 推理线程。三页原创《山路》从 CBZ 直接识别，用时分别为 776、684、1295 ms（每页含读取与解码，模型初始化另计）。识别的五个区域依次为「山／下」「入口」「山口／日出」。对照四句校对稿，漏识一个「の」，两个竖列需要合并，额外错并和倒序各零处。已经在本机工程修正「山の下」，对「入口」做一次拆分再合并，导出含四句原文的双文件修订。人工操作耗时与 Android 真机检索待试用者记录。[作者工具及命令](../../tool/comic_subtitles/README.md)

先在 Windows 作者工具中接一个本地 PP-OCR 适配器，按图片目录或 CBZ 中的章节建任务。每页保存原图尺寸、处理图到原图的变换、识别小框、方向、置信度与原始文字。作者能预览叠框、合并竖列、拆开相邻气泡、调整读序并修改校对文本。“屏译”的相册分段保存了整段与小框，其页面记录也保留两套尺寸，可据此设计适配输入。[屏译分段](https://github.com/ciddwd/overlay-translator/blob/64a7aa2c9605c88dd35bdeea42ab5c0f1c18ce5e/app/src/main/java/com/gameocr/app/gallery/GalleryTranslationModels.kt#L48) · [页面尺寸](https://github.com/ciddwd/overlay-translator/blob/64a7aa2c9605c88dd35bdeea42ab5c0f1c18ce5e/app/src/main/java/com/gameocr/app/gallery/GalleryTranslationDatabase.kt#L66)

**验收**　用可授权的真实样章记录模型版本、每页耗时、错并／错拆与读序错误数、人工校对用时。修正一处错字、合并和拆分各一次，导出后在阶段 2 的手机包上检索。无字页标记“未检出”，引擎失败页可单页重试。处理中途退出再打开，能从已保存页继续。发布过的对白改字沿用原 ID，合并或拆分时保留旧 ID 到新 ID 的对应。

## 4 · 按对白翻译并发布修订

作者工具已接入逐页批次、术语表、人工回包和兼容 Chat Completions 的文本服务。测试向本机回环服务发出了真实 HTTP 请求，另用乱序、重复、漏句和过期回包核对补译范围。英语与中文候选分别审校后可一起发布。云端模型的翻译质量需以用户选定的服务另行评估。[翻译回归](../../tool/comic_subtitles/test_translation.py)

作者选定原文和目标语言，可附本作品术语，按页和读序批量翻译。请求携带对白 ID 与原文修订，逐条接收能唯一对应当前原文的结果。乱序回包仍可使用，缺句、重复 ID、未知 ID 和过期回包进入复核。重跑产生候选，作者确认后更新。调用外部服务前展示接收方与将发送的文本，上送图像另行授权。逐页保存进度，日志记录阶段、数量与耗时。

**验收**　打乱回包、遗漏一句，再在请求期间改一处原文。补译后核对每条译文的归属和原文版本，已人工确认的修订仍可取回。增加第二种目标语言，导出新修订并重新挂载，分别用原文和两种译文找到对应气泡。模拟发布写入中断，上一份字幕仍可阅读。

## 5 · 两个工具交换字幕，再决定标准形态

0.1 候选采用 ACBF 加清单。Python 发布、Dart 改写相对引用并导出、Python 回读的结果保留了原始四边形、校对状态、拆并关系和多语历史。另一组向量让一个原文区域对应两个英文区域，另附同语的第二个译本。普通 CBZ 与带字幕 CBZ 均逐页核对了三张原创图片的字节摘要。单章归档可在阅读器中载入内附字幕并整章导出。协议、版本记录、向量与独立检查器已集中到 [spec/comic-subtitles](../../spec/comic-subtitles/README.md)。规范、程序及样图的迁仓许可待权利人确认。

把候选约定、正反样例、预期结果、校验命令和版本变更记录集中在 `spec/comic-subtitles/`。给独立工具作者该目录的副本，按其中的文字和样例实现。为 Dart 端补齐候选字幕导出，为桌面端补齐回读，实际走一遍双向交换。Flutter 界面、本地书库绑定、索引和 OCR 服务配置留在各自实现中。规范改动与应用适配按独立提交评审。[标准孵化目录](../../spec/comic-subtitles/README.md)

| 互通实验 | 评审证据 |
| --- | --- |
| 桌面写出，Dart 端读取、再导出，桌面重新读取 | 两端各自实现解析和写出，只共享规范和测试向量。逐字段比对页与对白 ID、原图摘要、读序、区域、语言、原始识别框、校对状态和拆并映射。增加原译框数不同和同语多译本的样例。 |
| 外挂单独传输、嵌入 CBZ、另存普通 CBZ | 归档导出展平章节、重命名图片时重写相对引用。若附有实验清单，按最终 ACBF 字节更新其绑定摘要。两种 CBZ 都逐页核对原图摘要，传统 CBZ 阅读器能打开图片，重新挂载字幕能找回原对白。[CBZ 导入导出](../../lib/features/local_comics/import_export/cbz.dart) |
| 比较 ACBF 兼容约定、ACBF 加清单、独立 sidecar 加 ACBF 转换 | 对每个候选标出能保留的字段、损失及旧读者行为。验证清单缺失、清单属于另一修订和未知必需能力时的提示。根据实测记录选择表示、扩展名、版本规则和兼容策略。 |

**拆仓条件**　两个独立实现完成上述往返，权利人确认规范、校验工具及样图的授权后，即可在 1.0 前迁出。迁移时带上目录历史、署名、历版向量与变更记录，旧目录保留到标准仓的入口。独立仓发布带版本的规范与离线测试包，应用固定到验证过的版本。互通失败的字段保留反例，在孵化目录修正后复测。

## 6 · 真机试用、回退与合入

在 Windows 11、Ryzen 5 6600H、Dart 3.11.4 上用 100 页、每页 100 句双语对白实测。一次预热后重建三次，耗时 91.3、82.4、79.9 ms。30 次查询的 P95 为 2.84 ms（「山」，一万条）、2.87 ms（「脚下」，一万条）、1.17 ms（指定一条）及 1.31 ms（无命中）。同机逐区域选择语言的基线分别为 23.32、23.04、21.47、21.65 ms。本轮保留内存子串检索，按页选择语言。[复现工具](../../tool/comic_subtitles/search_benchmark.dart)

设备试用工作流从同一提交生成含样章的试用入口，在 Windows 和两档内存的 Android 模拟器打开实际阅读器。每次进入前清空 Flutter 图片缓存，关闭与开启各三轮，从进入页面计时到首次观测到已解码原图，采集滚动期间引擎总帧耗时的 P95、32 ms 间隔采样的进程 RSS 峰值。Android 运行前开启飞行模式。报告包含检出 SHA、样章和原图指纹。实体手机触控、低内存设备与 TV 遥控器的结果由对应设备补录。[设备试用工作流](../../.github/workflows/subtitle-trial.yml)

从分支提交经 GitHub Actions 出测试包。以 `main` 为目标的草稿 PR 运行质量检查，里程碑提交手动运行 `build.yml`，选择 Android 和 Windows，关闭其余平台输入。Android 构建一次覆盖手机版和 TV 版。测试记录写明分支提交、工作流实际检出 SHA、Actions 链接、设备和样本修订，使回归可以用同一份产物复查。[质量检查](../../.github/workflows/analyze.yml) · [平台构建](../../.github/workflows/build.yml) · [测试清单维护](../development/testing.zh.md)

在同一提交、设备、样章和缓存条件下，关闭／开启字幕各做三轮冷开页及连续滚动，记录首图耗时、帧耗时 P95、峰值内存和字幕网络请求数。阶段 2 用首个读者包记录设备基线和波动范围，据此约定能接受的性能差值，后续各轮复用相同输入。另测低内存 Android 的降采样、TV 遥控焦点及桌面窗口缩放。用万句样本测索引构建时间和短词查询耗时，据实测决定是否引入全文索引。

**合入依据**　离线阅读的字幕网络请求为零，原图逐页摘要一致，错误版本得到提示，搜句能进对应气泡。发生错绑、人工修订丢失、原图损伤或翻页阻塞时，保留受影响样本，关闭实验开关即可继续读原图。修正后复跑相应阶段和普通漫画回归，再决定扩大试用。每批提交前同步 `CHANGELOG.md`，采用中文约定式提交。

局域网按页 OCR、在线源挂载、WebDAV 字幕同步、全库检索和朗读留到首轮试用后按需求排期。
