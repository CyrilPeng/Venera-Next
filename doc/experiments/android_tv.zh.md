# Android TV Alpha 实验记录（#120，历史）

2026-10-31：维护者确认 TV 版小范围测试完成，功能进入主线，后续随手机版共同构建和分发。当前安装、升级与构建方式请看 [Android TV 安装与分发](../distribution/android_tv.zh.md)（[English](../distribution/android_tv.en.md)）。本页以下保留合入前的隔离规则和验收表，不再作为当前操作指引；不合并 main、禁用应用更新、Alpha 版本码和手动分支限制均已由主线方案替代。

## 合入前记录

本实验仅在 `android-tv` 分支开发和手动构建，不合并 `main`，不创建普通版本标签，不更新稳定版／候选版 Release、AltStore 或 Winget。本分支的代码和自动化测试不等于 Android TV 真机验收，也不表示低内存崩溃已解决。

## 身份与安装隔离

| 项目 | 普通 Android | TV Alpha |
|---|---|---|
| Flavor | `mobile`（默认） | `tv` |
| 包名 | `com.github.cyrilpeng.veneranext` | `com.github.cyrilpeng.veneranext.tv` |
| 启动器 | VeneraNext | VeneraNext TV Alpha，支持电视入口和横幅 |
| 方向 | 沿用应用设置 | 固定横屏 |
| 应用更新 | 沿用正式版／候选版渠道 | 禁止查询普通应用更新；漫画源更新不受影响 |
| 数据 | 原沙盒 | 独立沙盒，不自动读取、迁移或删除手机版数据 |
| 版本 | `pubspec.yaml` 基础版本 | 保留基础版本，附 TV Alpha 构建标识和提交号 |

两个包可以共存。TV Alpha 仅供自愿测试；请先导出并另存数据备份，不要为了测试卸载手机版、清空原库或把两套应用指向同一个可写漫画／同步目录。不要同时从两套应用向同一 WebDAV 数据备份位置写入；需要同步测试时使用独立位置和副本。回退可卸载 TV 包，不影响手机版沙盒；TV 包自身数据仍应提前备份。

TV 原生基础构建号使用 `100000 + GitHub Run Number`，ABI 版本码沿用 `基础构建号 × 10 + ABI 标识`。同一次运行重试不增加版本码，显示标识包含重试次数；后续独立运行的构建可覆盖安装。该序列与普通发布构建号隔离，不修改 `release.json` 或漫画源读取的基础版本。

## 当前交互边界

- 主界面使用侧栏、可见焦点、安全边距和至少 1.1 倍字号。方向键移动焦点，确定／手柄 A 激活，返回／手柄 B 返回；支持菜单键的遥控器可打开控件上下文菜单。不要求鼠标悬停。
- 阅读画面获得焦点时，方向键交给现有阅读器翻页／滚动，确定打开菜单；菜单打开后方向键仅移动控件焦点，确定激活操作，不再触发背景翻页。
- 返回优先收起阅读菜单，再经过原有的保存／资源释放流程退出。失焦、菜单打开或切后台会取消持续按键，避免恢复后继续翻页。
- 这是复用现有界面的第一轮适配，不是完整的十英尺界面重设计。源的网页登录、验证码、文件选择器、第三方页面和某些细粒度手势可能仍需系统输入法、配套输入设备或后续适配；不能宣称所有操作已实现纯遥控器可达。

## 低内存策略

TV 默认开启「设置 → 阅读器 → TV 低内存模式」，仅保存在本机，不进入导出备份或 WebDAV，也不被导入设置覆盖：

- 有效配置为单页画廊、单页显示和 1 页预加载，暂停自动阅读模式识别；不改写已有的全局／本机／漫画阅读配置，关闭开关后恢复原配置。
- 图片缓存上限 64 MiB，先于异步内存查询应用；读取系统内存失败时继续保留上限。
- 阅读图片解码约束为最多 `1920 × 1080` 像素及 8192 像素最长边，不放大小图，不修改原始下载文件，保留原图尺寸元数据；可见图和预加载图采用相同策略及独立缓存键。
- 长条图和放大细节可能明显变糊。动画、解码临时缓冲、编码文件、原生插件和其他页面并不全部计入 Flutter 图片缓存；64 MiB 不是进程总内存上限，也不是不会 OOM 的保证。需要真机重复阅读和内存观测后再评估参数。

## 手动构建与产物

GitHub Actions 选择「构建」工作流，分支选择 `android-tv`，`android_flavor` 选择 `tv`，只开启 Android，其余平台全部关闭。例如：

```powershell
gh workflow run build.yml --ref android-tv `
  -f android_flavor=tv -f build_android=true `
  -f build_windows=false -f build_macos=false -f build_ios=false `
  -f build_linux_x64=false -f build_linux_arm64=false
```

工作流先执行复用的完整质量检查，包括普通 Flutter 全量测试与真正的 TV 编译参数测试；通过后构建签名 release APK。TV 仅接受此分支的手动触发，不通过普通标签发布渠道触发。

构建后检查全部 4 个 APK 的实际合并 Manifest、基础版本、独立版本码、原命名空间下的 MainActivity、电视入口／横幅／横屏／非触屏要求、签名及原生 ABI。任一变体失败都不上传 APK。TV 产物使用 `tv-apk-<ABI>-<提交号>`，不匹配普通 Release 的 `apk-*` 收集规则；文件名也包含 TV、基础版本、Alpha 构建标识和提交号。

另有 `tv-build-manifest-<提交号>`，其中 `build-manifest.json` 记录完整提交、构建身份、包名、各 ABI 版本码、签名证书 SHA-256、文件大小及文件 SHA-256。Artifacts 保留 14 天，需要登录 GitHub 下载；过期后应重新手动构建，不冒充永久 Release 链接。无法确定设备 ABI 时可选 universal，已知 ABI 时优先选择对应较小 APK。

本地构建使用项目固定的 Flutter 版本和原有 Android 签名配置：

```powershell
flutter pub get --enforce-lockfile
flutter build apk --release --flavor tv --build-number 100001 `
  --dart-define=TV_BUILD=local --dart-define=TV_REVISION=local
```

本地默认 `flutter build apk --release` 仍使用 `mobile`。本地示例不替代带完整提交和签名校验清单的 CI 构建；不要将本地实验包误当成经过云端检查的测试交付。

## 验收表（每个测试构建分别记录）

反馈请提供 TV Alpha 标识／提交号、设备型号、Android 版本、总内存／可用内存、遥控器类型、APK ABI、失败步骤与脱敏日志；不要求上传私人漫画、凭据或完整备份。

| 场景 | 预期与记录 |
|---|---|
| 安装与启动 | 与手机版共存；电视桌面显示横幅／独立名称；冷启动、重启后启动均可进入，手机版仍可运行 |
| 焦点可达性 | 仅用方向／确定／返回访问侧栏、列表、搜索、详情、章节和设置；列表滚动后焦点可见；进入／退出对话框恢复焦点，不陷入死角 |
| 文字和输入 | 720p／1080p／4K、大字体、明暗主题和减少动画设置下无阻挡操作；系统输入法可以输入／关闭，不误退出应用 |
| 阅读器 | 单页左右方向、连续／瀑布流（关闭低内存模式后）分别检查；菜单内方向不翻页；确定不连点；返回先收菜单，再保存退出，重进后页码正确 |
| 生命周期 | 长按方向键时切后台、断开遥控器、打开菜单／对话框，恢复后不继续翻页；保存失败仍保留退出保护 |
| 低内存 | 默认单页／1 页预加载；普通页、超长条图、大分辨率图、动画图和连续跨章重复阅读，记录耗时／峰值与稳定内存、卡顿和崩溃，不只记录缓存大小 |
| 配置和数据 | 开关切换后恢复原阅读模式；导入／备份／WebDAV 不传递低内存开关；退出、重启、覆盖升级后本机开关与阅读进度保留 |
| 更新隔离 | About 显示 TV Alpha 和提交；不提示安装普通 Android 更新；漫画源更新仍按原设置执行 |
| 手机版回归 | 构建 `mobile`，核对原包名、原启动入口／文件名、应用更新、方向设置及正常触摸；不启用 TV 焦点和低内存叠加 |

截至本轮开发，Windows 宿主上的静态检查、自动化输入／状态／真实 codec 测试可以验证代码路径；本机没有连接的 Android TV 或配置好的 Android 模拟器，不能将这些结果填为真机通过。云端 APK 成功与否以对应 Actions 运行结果为准；#120 保持开放，收到真机反馈后再决定下一轮适配和是否进入普通版本。
