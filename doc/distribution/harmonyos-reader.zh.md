# HarmonyOS 测试版安装与升级

鸿蒙测试版与其他平台共用主线的完整 Flutter/Dart 阅读器，通过独立鸿蒙 SDK 构建未签名 HAP，随主线版本分发。漫画源、阅读器、收藏、历史、下载和 WebDAV 复用原工程。**随版分发不代表全部系统能力适配或真机验收完成。**

本阶段直接提供应用日常试用，**不要求重复探针验证或私人附件**。后续版本遇到实际问题时，可通过新的 issue 反馈。

## 获取与安装

1. 在 [GitHub Releases](https://github.com/CyrilPeng/Venera-Next/releases) 选择提供鸿蒙包的版本，下载 `VeneraNext-版本-harmonyos-arm64-unsigned.hap`，不要使用 APK 或诊断探针。未提供 HAP 的历史版本不适用本指南；开发分支 Actions 产物也不等于已经发布。
2. 同一发布页还提供 `harmonyos-manifest.json`、`harmonyos-SHA256SUMS`、`harmonyos-install.zh.md` 和 `harmonyos-install.en.md`。安装前按摘要文件核对原始 HAP；签名会改变包体，原始摘要不能用于验证重签后的包。不要下载未知来源的重签名包。
3. 已有鸿蒙端小白调试助手的用户可沿用其现有环境，导入该 **未签名 HAP** 后由自己完成账号登录、设备授权、签名和安装。维护者不收集账号、设备标识、调试授权、证书或私钥；不附签名密钥、不绕过鸿蒙安全策略、不承诺自动续签。
4. 应用显示名为 `VeneraNext (HarmonyOS Beta)`，独立包名仍为 `com.github.cyrilpeng.veneranext.harmony`。它与旧诊断探针、卓易通内的 Android 包使用不同沙箱，不会自动共享那些应用的数据。

应用内版本及构建号与所在 Release 一致，可在 manifest 的 `build` 中核对。鸿蒙安装器显示三段数字版本名；若是 RC，完整预发布后缀保留在应用内，递增构建号用于区分升级。

从之前的实验包升级时，先导出并另存备份，沿用原包名和签名身份／密钥覆盖安装，不卸载、不清空数据。同一助手或账号不保证同一把密钥；若提示签名不匹配或必须卸载，先停止并反馈，不以卸载重装替代升级。应用沙箱副本会占用本机空间，请保留原漫画文件。参与 WebDAV 同步的设备应统一数据格式版本；回退使用升级前的独立备份，不让旧版本覆盖新版收藏库。

构建只声明 ARM64 `phone` / `tablet`，最低/目标 SDK 为 `26.0.0`。一位 MatePad / HarmonyOS 7.0 用户完成了核心探针，并在完整首包的日常使用中反馈“除目录导入外未发现其他问题”；这仅记录其使用范围，**不等于全功能、其他设备／系统、真实数据迁移或续签验收**。其他设备若不能安装，不要求其反复授权或降低系统安全设置。

## 直接开始使用

- 可在漫画源页面按原应用方式添加和安装源，再使用搜索、收藏、章节阅读、下载和历史。内嵌网页使用固定版本的 CPF Flutter OHOS WebView 适配；源自身的登录、验证和兼容性仍可能有问题。
- 本地「单个漫画」可选择图片目录，「多个漫画」可选择包含多本漫画子目录的父目录；仅在系统提供目录选择能力时可用。目录通过系统授予的 URI 复制到独占临时沙箱，保留原目录名／章节层次，再由现有流程复制到漫画库；不修改源文件，不保存临时路径作为长期漫画位置。
- 目录导入会显示复制、扫描、保存阶段，复制进度取自系统回调，不代表入库完成。结果窗口显示实际导入数及被跳过目录的原因，最多展示前 100 条详情；零本不会报成功，部分成功会保留。新导入避开旧配置收藏已占用的 ID，不删除或覆盖旧记录。
- 「漫画合集 ZIP」可将 `漫画甲/1.png`、`漫画乙/第1章/1.png` 分别导入，也自动识别一层可选总文件夹；无法区分多本漫画和单本漫画的章节时，会预览目录名并让你确认，取消不入库。普通「一个归档文件」的单本规则不变；不安全路径、链接、冲突或损坏数据会拒绝导入，原 ZIP 不修改，临时解压内容会在操作结束后清理。历史 `1.18.2-harmony.3` 包不包含上述 ID 与外层目录改进。
- 「多个归档文件」改为直接多选 CBZ / ZIP / 7Z / CB7，每个归档作为一本漫画，不再要求选目录。系统不提供目录选择、拒绝授权或复制失败时会给出批量归档替代提示；部分归档失败会显示具体文件及成功／失败数量，已成功导入的漫画保留。EPUB 仍从独立入口导入。
- 「设置 → App」保留 `data.venera` 备份导入/导出和 WebDAV 同步。先另存原数据备份和漫画文件，再按需迁移；配置导入不自动复制旧平台的外部漫画目录，也不保证恢复 Android SAF / Windows 路径。
- 导出的备份、图片和漫画通过系统保存选择器写入用户选择的文件，完成复制并关闭文件后才返回成功。请自行确认另存文件可见，再考虑清理旧副本；不建议把实验包当作唯一数据副本。
- 退出/后台时沿用现有阅读会话与异步收尾；下载仅在应用可运行的生命周期内执行，不保证绕过鸿蒙后台限制。
- 应用内检查更新只提示包含匹配版本未签名 HAP 和 manifest 的 Release，打开对应发布页后仍需自行签装；不会自动下载 APK 或替你签名安装。

## 明确的实验边界

- 目录只支持复制导入，不支持外部目录长期引用／自定义存储目录，设备目录选择能力仍以系统实际提供为准，不能用手机／平板声明代替真机验证。未接入系统分享、生物识别应用锁、Android 音量键/SAF/前台服务；分享请先保存到「文件」或复制文本，不假报成功。
- PDFium 没有 OHOS 构建，因此 **PDF 导入不支持**；现有 Dart PDF 导出保留。构建不会拿 Android/Linux PDFium 库凑包。PNG、ZIP、7Z 使用当前工程锁定源码的真实 OHOS 原生重编译库。
- 若导入配置含应用锁，实验包明确告知没有鸿蒙应用认证，由用户选择继续或退出，不自动伪装认证成功；可在设置中关闭导入的应用锁。
- 尚未验证 WebView 代理覆盖、平台图片编解码差异、完整应用网络/TLS/登录、大文件迁移、设备帧率/功耗、完整应用覆盖升级或签名续期。特别不要把 #91 的功耗收益算作本包已测得。
- UI、依赖解析、宿主回归、ARM64 ELF/FFI、包名/版本/API、原生库及资产校验只证明相应构建检查，不等于用户验收。

实际报错时请描述版本、使用的功能和错误，截图可自愿提供并遮盖私人信息；无需上传配置、Cookie、漫画源凭据、设备日志原件或签名材料。
