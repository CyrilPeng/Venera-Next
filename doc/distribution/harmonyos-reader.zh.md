# HarmonyOS 完整阅读器实验包

这是 `HarmonyOS` 分支复用现有 Flutter/Dart **完整应用工程**构建的实验 HAP，不是之前的空白包或核心诊断探针。漫画源、阅读器、收藏、历史、下载和 WebDAV 使用原工程，不另写一个简化阅读器。**完整工程编译不等于全部系统能力适配或真机验收**；正式支持平台和稳定 Release 不变。

按 #77 反馈者的意愿，本阶段直接提供应用日常试用，**不再要求重复四步验证、探针报告或私人附件**。遇到实际问题再在 #77 回复即可。

## 获取与安装

1. 从维护者在 #77 给出的成功 Actions 运行下载 `harmonyos-reader-experiment-运行号`，不要选择 `harmonyos-unsigned-lab-haps` 里的探针。Artifacts 需登录 GitHub，保留 14 天；过期时请向维护者索取新的构建，不下载未知重签名包。
2. 解压后应包含 `venera-next-1.18.2-harmony.3-arm64-unsigned.hap`、`full-app-manifest.json`、`SHA256SUMS` 及双语安装指南。核对原始 HAP 的摘要；小白签名会改变包体摘要，不能用原始摘要验证重签后的包。
3. 已有鸿蒙端小白调试助手的用户可沿用其现有环境，导入该 **未签名 HAP** 后由自己完成账号登录、设备授权、签名和安装。维护者不收集账号、设备标识、调试授权、证书或私钥；不附签名密钥、不绕过鸿蒙安全策略、不承诺自动续签。
4. 应用显示名为 `VeneraNext (HarmonyOS Lab)`，独立包名为 `com.github.cyrilpeng.veneranext.harmony`，版本 `1.18.2-harmony.3+3`。它与旧诊断探针、卓易通内的 Android 包使用不同沙箱，不是覆盖探针后自动出现原数据的升级包。

鸿蒙安装器中的原生版本名为 `1.18.2.3`、构建号为 `3`；这是 Flutter OH 要求的数字形式，与应用内的 `1.18.2-harmony.3+3` 属于同一个实验版本，不是主线正式版。

从之前的实验包升级时，先导出并另存备份，沿用原包名和签名身份／密钥覆盖安装，不卸载、不清空数据。同一助手或账号不保证同一把密钥；若提示签名不匹配或必须卸载，先停止并反馈，不以卸载重装替代升级。应用沙箱副本会占用本机空间，请保留原漫画文件。

构建只声明 ARM64 `phone` / `tablet`，最低/目标 SDK 为 `26.0.0`。一位 MatePad / HarmonyOS 7.0 用户完成了核心探针，并在完整首包的日常使用中反馈“除目录导入外未发现其他问题”；这仅记录其使用范围，**不等于全功能、其他设备／系统、真实数据迁移或续签验收**。其他设备若不能安装，不要求其反复授权或降低系统安全设置。

## 直接开始使用

- 可在漫画源页面按原应用方式添加和安装源，再使用搜索、收藏、章节阅读、下载和历史。内嵌网页使用固定版本的 CPF Flutter OHOS WebView 适配；源自身的登录、验证和兼容性仍可能有问题。
- 本地「单个漫画」可选择图片目录，「多个漫画」可选择包含多本漫画子目录的父目录；仅在系统提供目录选择能力时可用。目录通过系统授予的 URI 复制到独占临时沙箱，保留原目录名／章节层次，再由现有流程复制到漫画库；不修改源文件，不保存临时路径作为长期漫画位置。
- 目录导入会显示复制、扫描、保存阶段，复制进度取自系统回调，不代表入库完成。结果窗口显示实际导入数及被跳过目录的原因，最多展示前 100 条详情；零本不会报成功，部分成功会保留。复制失败时保留阶段／错误码，不需要上传私人日志。第二包的设备目录故障仍在排查，进度与结果提示不等于根因已经修复。
- 也可选择「漫画合集 ZIP」：例如 `合集.zip` 内直接放 `漫画甲/1.png`、`漫画乙/第1章/1.png`，每个根目录子文件夹导入为一本漫画。不要再套一层总目录；根目录直接放图片的普通 CBZ／ZIP 继续使用「一个归档文件」。不安全路径、链接、冲突或损坏数据会拒绝导入，原 ZIP 不修改，临时解压内容会在操作结束后清理。
- 「多个归档文件」改为直接多选 CBZ / ZIP / 7Z / CB7，每个归档作为一本漫画，不再要求选目录。系统不提供目录选择、拒绝授权或复制失败时会给出批量归档替代提示；部分归档失败会显示具体文件及成功／失败数量，已成功导入的漫画保留。EPUB 仍从独立入口导入。
- 「设置 → App」保留 `data.venera` 备份导入/导出和 WebDAV 同步。先另存原数据备份和漫画文件，再按需迁移；配置导入不自动复制旧平台的外部漫画目录，也不保证恢复 Android SAF / Windows 路径。
- 导出的备份、图片和漫画通过系统保存选择器写入用户选择的文件，完成复制并关闭文件后才返回成功。请自行确认另存文件可见，再考虑清理旧副本；不建议把实验包当作唯一数据副本。
- 退出/后台时沿用现有阅读会话与异步收尾；下载仅在应用可运行的生命周期内执行，不保证绕过鸿蒙后台限制。
- 后续实验包通过 #77 提供；应用内检查更新会提示该渠道，不把主线 Release 的 APK 等安装包当作 HAP 更新。

## 明确的实验边界

- 目录只支持复制导入，不支持外部目录长期引用／自定义存储目录，设备目录选择能力仍以系统实际提供为准，不能用手机／平板声明代替真机验证。未接入系统分享、生物识别应用锁、Android 音量键/SAF/前台服务；分享请先保存到「文件」或复制文本，不假报成功。
- PDFium 没有 OHOS 构建，因此 **PDF 导入不支持**；现有 Dart PDF 导出保留。构建不会拿 Android/Linux PDFium 库凑包。PNG、ZIP、7Z 使用当前工程锁定源码的真实 OHOS 原生重编译库。
- 若导入配置含应用锁，实验包明确告知没有鸿蒙应用认证，由用户选择继续或退出，不自动伪装认证成功；可在设置中关闭导入的应用锁。
- 尚未验证 WebView 代理覆盖、平台图片编解码差异、完整应用网络/TLS/登录、大文件迁移、设备帧率/功耗、完整应用覆盖升级或签名续期。特别不要把 #91 的功耗收益算作本包已测得。
- UI、依赖解析、宿主回归、ARM64 ELF/FFI、包名/版本/API、原生库及资产校验只证明相应构建检查，不等于用户验收。不自动关闭 #77，也不把该 HAP 发布到主线稳定渠道。

实际报错时在 #77 描述使用的功能和错误即可，截图可自愿提供并遮盖私人信息；无需上传配置、Cookie、漫画源凭据、设备日志原件或签名材料。
